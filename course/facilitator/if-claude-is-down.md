# If Claude is down

Print this page and keep it with the run of show.

## When to switch

- If Claude will not load on the projector laptop, try a phone hotspot [CONFIRM]. If it loads there, the problem is the venue Wi-Fi.
- If Claude does not work for most of the room within three minutes of an exercise starting, switch to this page for that topic. Try Claude again at the start of the next topic.
- Tell the room plainly: Claude is not answering, so we’ll do the checking part by hand. The checking is the habit, and it is the part that matters most.

## How every exercise runs without Claude

- **The idea:** no change.
- **The exercise:** walk through the four handout steps on the screen. Read each prompt aloud and say what it asks Claude to do and why. Then project the module’s `examples/flawed-draft.md` and say: this is what Claude gave back.
- **The check:** the room does step 4 by hand. They check the flawed draft against the printed sample files, using the handout checklist. This takes the exercise time as well as the mistake time, so there is room to go slowly.
- **The reveal:** from your printed answer key, as in [flawed-drafts.md](flawed-drafts.md).
- **Files:** use the printed sample files at each table, or the USB sticks, or the local copy on the projector laptop. The files link may not open without Wi-Fi.
- **Afterwards:** tell attendees to try the prompts at their desk next week, with the handout.

## What changes for each topic

1. **Weekly newsletter:** no Project to build, so explain on screen what goes into one. The room checks the facts table against `staff-notes.md` and `calendar.csv`. Still ask about Tuesday, March 10.
2. **AI use policy:** the room first marks each decision, open question and tabled item in `board-notes.md`. Then they check each rule in the flawed draft against those marks and the current policy.
3. **Prayer chain:** the room first finds the whole-church rows in `prayer-log.csv`. Then they check the email and card line by line against the request column. Still say the data safety line at the start and the end.
4. **Event announcements:** the room checks the table against the calendar and the leader’s email, and counts the first Tuesday from the April dates in the guide.
5. **Volunteer reminders:** the room applies the swap to the sign-up sheet in pen first. Then they check the reminder list name by name.
6. **Meeting minutes:** the room checks every motion, count, owner and date against `secretary-notes.md`, and ignores last month’s minutes.
7. **Bulletin and slides:** the room checks both ways: every slide line against the master, then every master item against the slides and the post.

## If the projector fails too

Hand out the printed flawed drafts, one per table, and run the same check on paper.
